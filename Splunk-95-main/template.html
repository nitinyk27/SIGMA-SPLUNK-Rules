Research: Relevance & Feasibility

The rules will run on Windows, so each Splunk rule is first checked for Windows relevance: does it read Windows telemetry? SigmaHQ is then the baseline: each Windows-relevant rule is checked against its best Windows Sigma match (relevance, feasibility, coverage). Where Sigma does not fully cover it, the Splunk rule is researched on its own: is it practical to deploy and is its detection logic sound? Every rule also gets a logic-test definition, listed here but not run. Click a tile, cell or row to drill in.

    Help

    What each score and label on this site means.

    How the Sigma matches were found

    Each Splunk search was broken into its indicators: quoted values, field values, and the process names behind macros such as `process_rundll32`. The same was done for the detection block of every active SigmaHQ rule. A pair's score combines weighted indicator overlap (rare strings count more than common ones like powershell.exe), title similarity, and whether both rules tag the same ATT&CK technique. Relevance scores whether the two rules target the same behaviour: a shared ATT&CK technique, similar names, the same telemetry (for example Endpoint.Processes and process_creation) and shared logic. Detection overlap compares the values each rule checks: the share of Splunk values that also appear in the Sigma rule and the reverse, plus exclusions and thresholds only one side has. Feasibility comes from converting the Sigma rule with pySigma and its Splunk backend: straight to a CIM tstats search (High), to raw Windows event SPL (Medium), or only without field mapping (Medium or Low). Experimental status, placeholders and regex lower it. Sigma coverage compares what the rules look for: Full cover means every value the Splunk rule looks for (process names, command-line strings, registry paths, event codes and so on) also appears in the Sigma rule; Partial cover means only some do; No cover means none do, or no Sigma rule was found. It compares values, not how the conditions combine them, so check the side-by-side view for extra conditions or exclusions on the Sigma side. Implementation readiness reads Splunk’s own metadata for each rule: the data sources and Splunkbase add-ons it needs, how common that telemetry is, the CIM data model, index macros, lookups, rule type and status, and whether Splunk publishes test data. Tactic names follow the current ATT&CK release, where Defense Evasion is split into Stealth and Defense Impairment.
